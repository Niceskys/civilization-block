## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是整理《文明块》早期任务系统的定位、边界、里程碑和 UI 表达，避免后续实现时把任务系统做成线性主线、强制教程或开局玩法门票。

本轮建议的核心判断是：

> 任务系统应记录文明如何成长，而不是决定玩家是否允许成长。

具体目标包括：

1. 明确任务系统在前期只承担引导、记录、轻提示和纪念作用。
2. 明确房屋、农田、水井、树场、第一次建造、第一次入住、第一次生产不应被任务领取卡住。
3. 明确玩家自由操作提前完成目标时，任务系统应自动识别，而不是要求按任务顺序重做。
4. 明确任务 UI 不能成为前30秒唯一入口，也不能用红点、强弹窗和强领取奖励驱动开局。
5. 明确早期任务奖励要避免伪造生产链，不能让玩家误以为资源凭空增长是核心玩法。
6. 明确任务清单应该围绕“基础城市闭环”组织，而不是围绕大量教学按钮组织。
7. 明确后续 Codex 回写时应分文件小步处理，不得一次性重写整个任务系统。

## 建议写入内容

待 Codex / 用户审核后回写。

### 一、任务系统早期定位

建议未来在 `10.1 任务系统通用规则.md` 中形成以下原则：

```md
### 早期任务系统定位

- 任务系统在前期只负责引导、记录、轻提示和纪念，不得成为基础玩法的唯一入口。
- 玩家不接任务，也应能够建造房屋、农田、水井、树场，完成基础城市闭环。
- 玩家通过自由建造提前完成任务目标时，任务系统应自动识别完成。
- 任务系统不得要求玩家按固定顺序重复已经完成的行为。
- 任务系统不得把开放经营建造改造成线性闯关主线。
- 任务提示可以帮助玩家理解下一步，但不得阻止玩家选择其他合理路径。
```

### 二、前30秒任务边界

```md
### 前30秒任务边界

- 新存档前30秒内，任务面板不得自动弹出。
- 任务系统不得自动抢占摄像机、锁定 UI、遮挡建造入口或阻止玩家观察城市。
- 前30秒允许后台记录里程碑，但不强制玩家打开任务面板。
- 前30秒最多允许出现一条非阻断轻提示，例如“建造第一座建筑”。
- 任务提示不得使用红点轰炸、强闪烁、强音效、签到样式奖励或现实时间错过惩罚。
- 玩家关闭任务提示后，本局不再强制显示同一提示。
```

### 三、基础城市闭环里程碑建议

建议早期任务不要围绕“点按钮”，而应围绕城市真实发生的变化：

```md
### 基础城市闭环里程碑

可记录的早期里程碑包括：

1. 第一次打开建造面板。
2. 第一次确认合法建筑放置。
3. 第一座建筑进入施工状态。
4. 第一次 NPC 参与施工。
5. 第一座建筑完成。
6. 第一座房屋完成。
7. 第一位 NPC 入住房屋。
8. 第一座基础生产建筑完成。
9. 第一次分配 NPC 到工作岗位。
10. 第一条基础生产链开始运转。
11. 第一次正式资源产出入库。
12. 第一次发现建筑可以向上堆叠或进入三维建造提示。

这些里程碑应由权威事件自动触发，不要求玩家先接任务。
```

### 四、建议早期任务组

建议未来 `10.2 任务清单.md` 可以围绕以下任务组重排，但本轮不得直接回写：

```md
### 早期任务组建议

#### A. 城市启动组
- 观察初始地皮
- 建造第一座建筑
- 看到第一段施工反馈
- 完成第一座建筑

#### B. 住房闭环组
- 建造第一座房屋
- 第一位 NPC 入住房屋
- 查看房屋住户状态
- 让至少一名 NPC 拥有床位

#### C. 基础生产组
- 建造农田 / 水井 / 树场中的任意一座
- 分配或等待 NPC 开始工作
- 第一次获得正式产出
- 理解输入 / 输出 / 空闲 / 待分配状态

#### D. 木材稳定组
- 建立树场或其他稳定木材来源
- 避免木材完全断供
- 为后续建筑和工具制造做准备

#### E. 人口与工作组
- 查看 NPC 状态
- 给 NPC 分配第一个岗位
- 识别空闲 NPC
- 识别待分配建筑

#### F. 立体建造发现组
- 进入建造模式
- 悬停到可堆叠建筑上方
- 看到顶部网格
- 完成或预览第一次向上建造

#### G. 工具与专业化预告组
- 在基础闭环后解锁工具制造提示
- 制作或获得第一件正式工具
- 理解工具用于效率、采掘、维修或专业化，而不是开局门票
```

### 五、任务奖励边界

```md
### 任务奖励边界

- 任务奖励不得伪造第一次资源增长。
- 如果任务奖励资源，必须明确它是任务奖励，而不是建筑生产产出。
- 第一条基础生产链的首次产出应来自正式生产系统，而不是任务系统伪装。
- 前期任务奖励应以轻量资源、解锁提示、文明记忆、图鉴记录、少量星辉或非关键便利为主。
- 不得通过任务奖励绕过第一座熔炉房冷启动、基础生产链或正式资源获取路径。
- 不得用任务奖励强迫玩家进入商店、签到、每日奖励或现实时间活动。
```

### 六、任务 UI 表达建议

```md
### 任务 UI 表达建议

- 任务入口可以存在，但不得在前30秒成为最显眼的唯一入口。
- 任务完成提示应轻量、非阻断，不遮挡建造、资源栏或建筑反馈。
- 任务列表应允许玩家晚点查看，不应因为未查看而阻止任务自动完成。
- 已完成但未领取的任务不得用强红点持续压迫玩家。
- 可以使用柔和提示，例如“城市记住了这一步”“新的发展记录已生成”。
- 任务 UI 应显示任务是建议路径，而不是唯一正确路径。
```

### 七、任务与权威事件流建议

```md
### 任务与权威事件流

- 任务系统应监听正式事件流，而不是直接改写建筑、资源、NPC 或时间状态。
- 可监听的事件包括：建筑放置确认、施工任务创建、建筑完成、NPC 入住、NPC 分配岗位、生产批次完成、资源入库、探索完成。
- 任务完成只记录玩家已经做到的事情，不反向决定该事情是否有效。
- 如果 UI 或任务面板刷新失败，不得导致资源重复发放、建筑重复完成或 NPC 重复入住。
- 任务奖励发放必须经过正式奖励结算流程，避免重复领取和读档复制。
```

### 八、反线性主线建议

```md
### 反线性主线边界

- 任务清单可以提供推荐顺序，但不得把所有玩家锁进同一条线性主线。
- 玩家先建农田再建房屋、先建水井再建树场、先观察再建造，都应被系统容纳。
- 任务系统应识别多种合理路径，而不是只识别单一路径。
- 任务不应阻止玩家自由摆放、移动、重新放置或尝试不同基础建筑顺序。
- 任务失败不应成为早期失败条件；早期任务更适合可补做、可自动完成或可转为历史记录。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 《文明块》的核心是开放经营建造，不是线性任务闯关；任务系统必须服务这个核心。
2. 早期任务如果太强，会让玩家误以为“先接任务才能玩”，削弱自由建造感。
3. 玩家前期最需要看到城市响应，而不是被任务面板打断。
4. 自动识别玩家已完成行为，可以容纳不同玩法顺序，也减少新手挫败。
5. 任务系统如果直接发放大量关键资源，会破坏生产链的可信度和第一轮资源闭环。
6. 任务 UI 如果使用强红点、签到、日常奖励，会把游戏气质拉向移动端强运营，而不是精细体素经营建造。
7. 把任务定位为“文明记忆”和“成长记录”，更适合《文明块》的长期体验。
8. 本建议与前30秒留存边界、基础城市闭环、NPC 反馈闭环、工具制造前期边界相互配套，应作为完整主题包处理。
