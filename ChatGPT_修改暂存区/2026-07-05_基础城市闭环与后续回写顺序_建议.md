## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是把前面多个暂存建议合并成一个更完整的“基础城市闭环”问题包，减少后续每次只处理一点点内容的低效率。该建议用于指导 Codex / 用户后续审核和回写顺序，而不是直接修改正式规则。

本轮建议聚焦《文明块》前期体验中最关键的一条完整链路：

> 进入新存档 → 看懂城市等待启动 → 第一次建造 → 第一座房屋 / 基础生产建筑 → NPC 有反应 → 资源链开始自转 → 玩家理解下一步成长方向。

本轮希望一次性整理以下内容：

1. 前30秒不强制教程、不红点驱动、不伪造资源。
2. 建筑放置必须有清晰合法性反馈，地形细节不能让玩家难以建造。
3. 基础建筑不应被工具制造、任务领取、复杂 UI 或深层系统卡住。
4. NPC 入住、施工、空闲、待分配等反馈要帮助玩家理解城市在响应。
5. 任务系统只记录和轻提示，不成为基础建造的门票。
6. 工具、地下挖掘、复杂地形整备、深层生产链应放在基础闭环之后逐步展开。
7. 给出后续正式回写的建议顺序，避免 Codex 一次性大改正式目录。

## 建议写入内容

待 Codex / 用户审核后回写。

### 一、基础城市闭环总原则

建议未来在适当的正式文件中形成以下原则，但本轮不得直接回写：

```md
### 基础城市闭环原则

- 新存档的第一目标不是让玩家读懂全部系统，而是让玩家完成第一次可信的城市响应。
- 第一轮基础闭环应包含：可建地皮、第一座建筑、NPC 响应、资源栏变化、建筑完成反馈、下一步轻提示。
- 房屋、农田、水井、树场等基础建筑不得被工具制造、任务领取、复杂科技、商店购买、深层挖掘或高级资源链阻塞。
- 任务系统可以记录玩家完成了什么，但不得成为玩家允许开始建造的前置条件。
- UI 可以提示玩家下一步，但不得通过强制弹窗、红点、签到、现实时间错过惩罚来驱动前30秒留存。
- 视觉表现可以丰富，但不能伪造资源增长、伪造生产结果或绕过正式模拟。
```

### 二、新存档前30秒建议

```md
### 新存档前30秒建议

- 进入新存档后，世界处于等待启动状态，玩家可以观察、旋转视角、查看资源和打开建造面板。
- 玩家第一次合法确认建筑放置前，不应受到时间、怪物、随机事件、资源衰减或危机惩罚。
- 前30秒只展示最低必要信息：资源栏、建造入口、初始地皮可建状态、NPC 存在感和一个非强制推荐行动。
- 不自动打开建造面板。
- 不使用强制教程弹窗。
- 不使用红点、签到奖励、现实时间奖励或错过惩罚。
- 第一条提示可以是底栏轻提示：`[B] 建造第一座建筑`。
- 玩家关闭提示后，本局不再重复强制显示同一提示。
```

### 三、第一次建造建议

```md
### 第一次建造建议

- 建造面板应默认推荐房屋，但不锁死其他基础建筑选择。
- 房屋、农田、水井、树场都应可以作为前期可理解的第一轮基础建筑候选。
- 玩家选择建筑后，应显示建筑虚影、占地范围、地基面和合法性反馈。
- 合法位置显示绿色或青色虚影。
- 非法位置显示红色虚影，并给出简短原因。
- 小草、碎石、轻微贴图起伏不得单独阻止建筑放置。
- 高差过大、缺少地基面、越界、承重不足、通行阻塞、未拥有地皮等原因可以阻止建筑放置。
- 玩家确认第一次合法建筑放置后，才触发正式时间启动和施工任务创建。
- 放置失败、取消、仅预览、仅打开建造面板均不触发正式时间启动。
```

### 四、第一次城市响应建议

```md
### 第一次城市响应建议

- 第一次合法放置后，城市必须立刻给出可见反馈。
- 可见反馈至少包含以下两项：建筑虚影 / 施工边框 / 施工进度 / NPC 走向工地 / 资源栏扣除或锁定 / 建筑材料出现。
- 施工中的 NPC 行为应以“城市开始动起来”为目标，不需要复杂 AI，但必须能让玩家看懂有人在建设。
- 第一座建筑完成时，应至少出现以下两项反馈：建筑落地、外观变化、轻音效、轻粒子、窗口亮起、NPC 入住或进入工作状态。
- 如果第一座建筑是房屋，应优先展示 NPC 自动入住、窗口暖光、床位状态变化。
- 如果第一座建筑是生产建筑，应显示“空闲 / 待分配 / 可工作”，不得直接用红色危机误导玩家。
- 不得伪造第一次资源增长；第一次资源增长必须来自正式生产、任务奖励、勘探奖励、事件奖励或商店交易。
```

### 五、基础建筑与工具制造边界建议

```md
### 基础建筑与工具制造边界建议

- 工具制造系统不作为第一座房屋、第一座农田、第一口水井或第一座树场的前置条件。
- 前30秒内不得强制玩家理解工具等级、工具耐久、工具配方或工具更换。
- 工具系统更适合在基础住房、基础生产、木材来源和初始 NPC 响应建立后出现。
- 工具可以影响中后期施工效率、维修效率、采掘效率、地下挖掘层级或专业岗位效率。
- 深层挖掘和特殊矿脉可以保留工具门槛，但不得反向阻塞地面基础城市闭环。
- 如果未来工具影响施工速度，首次建造加速仍应优先成立，工具加速不得直接与首次建造加速叠加。
```

### 六、任务系统边界建议

```md
### 任务系统边界建议

- 任务系统在前期应记录、轻提示和纪念，而不是控制玩家能不能开始建造。
- 可记录的早期里程碑包括：第一次打开建造面板、第一次合法放置建筑、第一座建筑完成、第一位 NPC 入住、第一条生产链启动。
- 不得要求玩家先接任务才能建造房屋、农田、水井或树场。
- 不得把“点击任务按钮”做成前30秒唯一入口。
- 任务提示应可忽略，玩家通过自由建造完成同样行为后，任务也应能识别完成。
- 工具制造任务应出现在基础城市闭环之后，不应排在第一座基础建筑之前。
```

### 七、NPC 反馈边界建议

```md
### NPC 反馈边界建议

- 开局 NPC 应提供城市存在感，但不得在第一次合法建筑放置前消耗资源、触发危机或制造惩罚。
- NPC 可以在初始地皮上待机、观察文明核心、短距离走动或表现等待状态。
- 第一次施工任务创建后，至少一名可用 NPC 应进入施工相关表现，除非正式规则判定没有可用工人。
- 房屋完成后，如果有符合条件的 NPC，应显示入住反馈。
- 生产建筑完成后，如果没有工人，应显示“待分配 / 空闲”，不要直接显示严重错误或危机状态。
- NPC 的视觉动作只解释权威状态，不直接决定资源产出或施工完成。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 用户已经明确表示不希望每次只生成一点点内容，因此本轮把多个高度相关的前期体验问题打包成一个完整问题包。
2. 《文明块》的早期体验如果拆得太碎，容易出现文件之间互相打架：UI 说可以建造，工具系统说不能建造，任务系统又要求先接任务，建筑系统又缺少地形合法性说明。
3. 基础城市闭环是后续所有系统的地基；如果这个闭环不清楚，后期联机、模组、地下探索、工具制造、任务系统都会越来越难统一。
4. 使用暂存区建议文件，可以让 Codex / 用户先审核方向，不直接污染正式 A 级规则。
5. 把“建议影响的正式文件”和“后续回写顺序”写清楚，可以避免 Codex 一次性大改全部正式目录。
6. 前30秒、第一次建造、NPC 响应、任务边界、工具边界、地形合法性本质上属于同一个前期体验闭环，应该一起审查。
7. 本建议不直接生效，可以保留设计弹性，也能降低误改 `00.3`、`00.4` 和正式文档的风险。
