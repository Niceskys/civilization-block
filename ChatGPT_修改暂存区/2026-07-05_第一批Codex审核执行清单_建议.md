## 建议写入内容

待 Codex / 用户审核后回写。

### 一、范围审核清单

后续检查 Codex 结果时，先确认：

- 是否只修改第一批允许文件。
- 是否没有修改 `00.3`、`00.4`。
- 是否没有修改 Runtime / C# / Unity / 测试代码。
- 是否没有新增正式目录文件。
- 是否没有创建 PR，除非用户明确要求。
- 是否没有把暂存区建议称为已生效规则。
- 是否没有把三份深度研究报告原文整篇搬入正式文档。
- 是否没有一次性覆盖已有正式规则。

### 二、MVP 冻结审核清单

后续检查 Codex 结果时，确认正式文档是否明确回答：

- MVP 是小型体素城市样机，不是缩小版完整游戏。
- MVP 必须围绕第一轮基础城市闭环。
- MVP 必须包含房屋、农田、水井、树场。
- MVP 必须包含木材、食物、水、人口、空闲工人。
- MVP 必须包含建造 UI、资源栏、建筑详情 UI、轻量下一步提示。
- MVP 必须包含最小 NPC 劳动力反馈。
- MVP 必须包含手动存档 / 读档这个目标，但具体存档结构不在第一批展开。

### 三、基础城市闭环审核清单

后续检查 Codex 结果时，确认基础闭环是否被写成：

木材驱动建造 → 房屋提供居住容量 → 水井提供水 → 农田消耗水并产出食物 → 城市按人口聚合消耗食物与水 → 空闲 NPC 自动补位到生产 / 施工岗位 → 树场提供可再生木材继续扩张。

同时确认：

- 没有把熔炉房写成 MVP 必做。
- 没有把铁矿石、铁锭、燃料链写成 MVP 必做。
- 没有把工具链写成 MVP 必做。
- 没有把商店补货写成基础闭环必需。
- 没有把任务奖励资源池写成基础资源来源。

### 四、前30秒审核清单

后续检查 Codex 结果时，确认前30秒规则是否满足：

- 允许出现初始地皮。
- 允许出现资源栏。
- 允许出现暂停 / 等待启动状态。
- 允许出现建造入口。
- 允许出现四个基础建筑卡。
- 允许出现少量 NPC 存在感。
- 允许出现一个非强制轻提示。

同时确认前30秒不得自动打开：

- 任务面板。
- 商店面板。
- 地下探索面板。
- 工具制造面板。
- 科技树面板。
- 完整 NPC 管理面板。
- 联机入口。
- 模组入口。

### 五、建筑审核清单

后续检查 Codex 结果时，确认四个基础建筑职责没有扩大：

房屋：只承担居住容量、入住反馈、人口稳定入口；不做家庭关系、生育、舒适度、情绪、社交、复杂室内模拟。

农田：只承担消耗水、周期产食物、工位、暂停原因；不做多作物、季节、肥料、病虫害、复杂光照、地下水系统。

水井：只承担基础水来源、支撑人口与农田；不做地下水位、水质、污染、水桶物流、井深升级、地下联动。

树场：只承担可再生木材、工位、产木反馈；不做逐棵树模拟、林业生态、应急炭化、燃料链、工具效率链。

建筑通用规则需保留：

- 选择建筑。
- 放置预览。
- 合法性检查。
- 确认建造。
- 扣除或锁定资源。
- 进入施工。
- NPC 施工响应。
- 完成建筑。
- 建筑详情显示状态与等待原因。

### 六、NPC 审核清单

后续检查 Codex 结果时，确认 NPC MVP 边界是：

必须真实保留：

- 人口数。
- 空闲 / 占用工人。
- 施工参与。
- 基础生产岗位占用。
- 房屋入住状态。
- 城市级食物 / 水消耗。
- 建筑等待原因中的工人状态。

不得写成 MVP 必做：

- 职业成长。
- 情绪。
- 恐惧。
- 社交。
- 好感度。
- 个体记忆。
- 完整路径驱动生产结算。
- 个体吃饭喝水行为。
- 个体生命周期细节。
- 家庭关系。

### 七、UI 审核清单

后续检查 Codex 结果时，确认 UI MVP 边界是：

全局 UI 至少包含：木材、食物、水、人口、空闲工人、时间 / 暂停状态、建造入口、轻量下一步提示。

建造 UI 只展示四张基础建筑卡：房屋、农田、水井、树场。

建筑详情 UI 至少显示：名称、当前状态、施工 / 运行 / 暂停、工位状态、输入资源、输出资源、等待原因、可用 / 不可用原因。

NPC UI 只显示：总人口、空闲工人、占用工人、施工中人数、生产岗位占用、房屋入住状态。

不得写成 MVP UI：

- 任务红点。
- 商店促销。
- 每日签到。
- 限时礼包。
- 地下入口强提示。
- 工具制造入口强提示。
- 科技树入口。
- 联机入口。
- 模组入口。

### 八、禁止越级审核清单

后续检查 Codex 结果时，只要出现以下情况，就应要求回退或拆分：

- 把正式任务系统写入 MVP。
- 把正式商店经济写入 MVP。
- 把地下探索玩法写入 MVP。
- 把工具制造链写入 MVP。
- 把熔炉房、铁矿石、铁锭、燃料链写入 MVP。
- 把怪物 / 防御战写入 MVP。
- 把职业、情绪、社交、记忆写入 MVP。
- 把完整联机、完整模组 API、完整 ECS / DOTS 写入 MVP。
- 修改 Runtime / C# / Unity / 测试代码。
- 修改 `00.3` 或 `00.4`。
- 新增正式目录文件。

### 九、通过标准

第一批 Codex 结果只有同时满足以下条件，才建议进入下一步审核：

1. 所有修改都在第一批允许文件范围内。
2. MVP 范围比原来更清楚，而不是更大。
3. 基础城市闭环被写清楚。
4. 四个基础建筑职责被写清楚。
5. NPC 被限制在最小劳动力边界内。
6. UI 被限制在解释和轻提示边界内。
7. B / C 级系统被明确延后。
8. 没有修改代码和工程文件。
9. 没有修改 `00.3`、`00.4`。
10. 没有新增正式目录文件。

## 理由

待 Codex / 用户审核后回写。

提出本清单的理由如下：

1. 第一批正式回写涉及多个正式文件，如果没有审核清单，容易越界。
2. Codex 容易把暂存建议中的中后期内容提前写进 MVP，因此必须设置禁止越级检查。
3. 当前目标是冻结 MVP，而不是扩大系统。
4. 审核清单比直接执行指令更安全，便于用户和 Codex 对照。
5. 本清单能帮助后续判断“是否可以进入第二批 Runtime 与数据模型边界回写”。
