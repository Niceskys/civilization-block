## 三、方案目标

后续正式回写不得新增 UI 实现，不得新增系统入口，不得修改 Runtime，不得修改 C# / Unity / 测试代码。

## 四、后续正式回写只应补充的内容

### 1. 全局 UI 只能读取 Runtime 输出

后续正式回写只建议补充以下边界：

- 全局界面只能读取 Runtime State / Event / Diagnostics / ViewState 等输出。
- 全局资源栏、人口、工人、时间、暂停/倍速、提示、诊断摘要、建筑状态入口等展示应以 Runtime 输出为准。
- UI 不得直接修改权威 State。
- UI 不得自行裁决资源变化、人口变化、工人状态、时间推进、建筑运行状态或诊断优先级。

### 2. 全局 UI 只能提交 Command

后续正式回写只建议补充以下边界：

- 全局 UI 如需触发暂停、倍速、建造入口、建筑选择、任务入口、提示响应等玩家操作，只能提交 Command 或进入只读 View 流程。
- UI 不得直接扣资源。
- UI 不得直接创建建筑。
- UI 不得直接推进时间。
- UI 不得直接修改 NPC / 岗位 / 生产 / 库存 / 建筑状态。
- UI 不得绕过 CommandBus / Simulation。

### 3. 诊断与提示边界

后续正式回写只建议补充以下边界：

- 全局提示、诊断摘要、警示状态可以展示 Runtime Diagnostics。
- UI 可以展示 DiagnosticIssue 的结构化字段。
- UI 不得解析自然语言 Message 作为规则来源。
- UI 不得维护第二套诊断优先级。
- UI 不得复制生产、库存、物流、承重、光照、燃料、消耗算法生成提示。

### 4. 长期入口边界

后续正式回写只建议补充以下边界：

- 商店、任务、科技、事件日志、数据仪表盘、挑战等长期入口如果存在于全局 UI，只能作为入口或只读展示。
- 不得让这些入口在当前阶段成为 MVP 必做。
- 不得让这些入口直接修改 Runtime 权威状态。
- 需要实际修改状态时，必须通过后续正式 Command / Simulation 规则裁决。
