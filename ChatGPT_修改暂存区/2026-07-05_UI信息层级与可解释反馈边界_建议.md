## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是在访问当前仓库并确认暂存区已有主题后，补充一个新的完整主题包：UI信息层级与可解释反馈边界。当前暂存区已有前30秒、建筑放置、NPC、任务、商店、资源链等主题，但这些主题都分别提到 UI，尚缺一个统一的 UI 信息层级总边界。

本建议的核心判断是：

> UI 应解释权威状态、降低玩家理解成本，而不是制造强制引导、伪造结果或替代游戏系统。

建议目标包括：

1. 明确全局 UI、建造 UI、建筑详情 UI、NPC UI、任务 UI、商店 UI 之间的信息层级。
2. 明确 UI 不得直接修改资源、建筑、NPC、任务、时间、生产、战斗等权威状态。
3. 明确所有重要失败都应给出可解释原因，而不是笼统显示“错误”“停产”“不可用”。
4. 明确前30秒 UI 只显示最低必要信息，不强制弹窗、不红点轰炸、不遮挡城市响应。
5. 明确建筑放置、生产等待、NPC 空闲、商店交易、任务完成、地下探索等反馈必须可理解、可恢复、可追踪。
6. 明确后续 Codex 回写应优先补 UI 边界和文案规则，再考虑具体界面布局和实现。

## 建议写入内容

待 Codex / 用户审核后回写。

### 一、UI 总定位

建议未来在 `5.1 全局界面.md` 或 UI 总则中形成以下原则：

```md
### UI 总定位

- UI 的职责是展示、解释、引导和确认，不是直接决定权威游戏状态。
- UI 不得直接修改资源、建筑、NPC、任务、时间、生产、战斗、存档或联机状态。
- 玩家通过 UI 发起的操作必须转化为正式 Command，再由 Simulation Layer 校验后执行。
- UI 显示应来自权威状态、ViewState 或正式事件流，不得凭空伪造资源增长、生产完成、NPC 入住或任务完成。
- UI 信息应按玩家当前阶段逐步展开，不应在前30秒展示全部系统复杂度。
```

### 二、前30秒 UI 信息层级

```md
### 前30秒 UI 信息层级

- 前30秒只显示最低必要信息：资源栏、建造入口、初始地皮可建状态、NPC 存在感和一个非强制推荐行动。
- 不自动打开任务面板、商店面板、NPC 管理面板、科技面板或地下探索面板。
- 不使用强制弹窗教程。
- 不使用红点轰炸、强闪烁、强音效、遮挡式箭头或必须点击才能继续的遮罩。
- 底栏提示应轻量，例如“建造第一座建筑”，并允许关闭。
- 首次城市响应期间，UI 不得遮挡建筑施工反馈、NPC 施工反馈、房屋入住反馈或资源栏变化。
```

### 三、全局 UI 层级建议

```md
### 全局 UI 层级建议

全局 UI 信息建议分为四层：

1. 常驻核心层：资源栏、时间 / 暂停状态、建造入口、重要城市状态。
2. 当前操作层：建造预览、选择目标、确认 / 取消、合法性反馈。
3. 轻提示层：下一步建议、里程碑完成、温和等待原因。
4. 警告层：资源断供、严重危机、怪物攻击、建筑失效、不可恢复风险。

前期默认只启用常驻核心层、当前操作层和少量轻提示层。
警告层必须有明确权威原因，不得为了留存或引导滥用红色警告。
```

### 四、建造 UI 可解释反馈

```md
### 建造 UI 可解释反馈

- 建筑预览必须显示占地范围、地基面和放置合法性。
- 合法位置显示绿色或青色虚影。
- 非法位置显示红色虚影，并给出简短原因。
- 非法原因应优先归类为：未拥有地皮、未接入地皮、占地冲突、地基不足、承重不足、通行受阻、特殊地貌限制、资源不足、建筑类型限制。
- 小草、碎石、轻微颗粒起伏不得显示为硬阻挡原因。
- 如果高差过大，应显示“高差过大，需要平台、地基或支撑”。
- 如果缺少承重，应显示“承重不足，需要支撑结构”。
- 如果门口不可达，应显示“入口通行受阻”。
- 不得只显示“不可建造”而不解释原因。
```

### 五、建筑详情 UI 可解释反馈

```md
### 建筑详情 UI 可解释反馈

- 建筑详情 UI 应显示建筑当前状态、输入资源、输出资源、工人 / 住户、库存、等待原因和可操作项。
- 生产建筑等待时，应显示具体原因：缺少输入、缺少燃料、缺少工人、产物满仓、路径阻塞、建筑损坏、暂停中。
- 房屋应显示住户、床位、入住状态和是否有空床。
- 熔炉房应显示铁矿石、燃料、铁锭产出、工人、产物转移状态。
- 树场应显示木材产出、是否可应急炭化、当前工作状态。
- 不得用笼统“停产”“错误”“不可用”替代具体等待原因。
- 建筑状态文案应优先帮助玩家恢复运转，而不是制造恐慌。
```

### 六、NPC UI 可解释反馈

```md
### NPC UI 可解释反馈

- NPC 管理 UI 前期应优先显示姓名、状态、住房、当前工作、是否空闲。
- NPC 空闲应显示为中性状态，例如“空闲中”“等待任务”“暂无岗位”。
- NPC 无房在第一座房屋完成前不应强红警告，可显示“等待住房建设”。
- NPC 未分配工作时，应显示“可分配工作”或“暂无岗位”，并提供入口。
- NPC 参与施工、入住、工作时，UI 应与场景表现一致。
- 不得让 NPC UI 在前30秒展示完整恐惧、好感、社交、记忆、性格等复杂信息压迫玩家。
```

### 七、任务 UI 可解释反馈

```md
### 任务 UI 可解释反馈

- 任务 UI 应表达“建议路径 / 成长记录 / 文明记忆”，而不是“唯一正确主线”。
- 任务完成提示应轻量、非阻断，不遮挡建造反馈和城市响应。
- 任务奖励必须标注来源为任务奖励，不得伪装成生产产出。
- 已完成但未领取的任务不得用强红点持续压迫玩家。
- 玩家自由操作提前完成目标时，任务 UI 应显示已完成，而不是要求重做。
- 前30秒不得自动弹出任务面板。
```

### 八、商店 UI 可解释反馈

```md
### 商店 UI 可解释反馈

- 商店商品应显示价格、库存、阶段、用途、是否限量、是否应急补给。
- 商店购买获得的资源必须标注为购买或交易获得。
- 商店不应在前30秒自动弹出。
- 商店不得使用签到、每日礼包、限时倒计时、现实时间错过惩罚作为核心 UI。
- 防卡死商品可以显示为“应急补给”，但不得用强红点压迫玩家。
- 如果玩家已有稳定生产链，商店可提示“自产更划算”或“临时购买可补缺”。
```

### 九、地下探索 UI 可解释反馈

```md
### 地下探索 UI 可解释反馈

- 地下入口应显示所属地皮、当前可探索层级、工具需求、风险等级和等待原因。
- 不可挖掘时，应显示明确原因：未拥有地皮、未探索地皮、缺少入口、工具不足、危险未处理、建筑阻挡。
- 工具不足应显示“需要更高等级工具”或“当前只能探索浅层”。
- 地下资源显示应阶段性展开，不应初期直接暴露所有深层资源。
- 地下探索失败、暂停或等待时，应显示可解决原因，不应显示系统错误。
```

### 十、资源来源与事件反馈建议

```md
### 资源来源与事件反馈

- 建筑生产获得的资源应标注为对应建筑产出。
- 商店购买获得的资源应标注为购买或交易获得。
- 任务奖励获得的资源应标注为任务奖励。
- 探索获得的资源应标注为探索、勘探或事件获得。
- 拆除返还获得的资源应标注为拆除返还。
- 不得让 UI 把购买、任务奖励、探索奖励伪装成第一次生产产出。
- 资源变化提示应可追踪，避免玩家不知道资源为什么增加或减少。
```

### 十一、警告等级建议

```md
### 警告等级建议

UI 警告建议分为四级：

- 信息：普通提示，例如“建筑已完成”“居民已入住”。
- 等待：可恢复状态，例如“缺少工人”“等待燃料”“产物待转移”。
- 风险：如果不处理可能造成损失，例如“食物即将不足”“建筑耐久较低”。
- 危机：正在造成损失或立即威胁，例如“怪物攻击”“关键资源断供”“建筑失效”。

前期不应把“空闲”“待分配”“等待住房”直接显示为危机。
红色警告必须对应真实权威风险，不得为了吸引点击滥用。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 当前暂存区已有多个系统边界，但很多都分别提到 UI；如果没有统一 UI 信息层级，后续正式回写容易互相冲突。
2. 《文明块》系统复杂，玩家必须通过 UI 理解“为什么不能建造”“为什么停产”“为什么 NPC 空闲”“为什么资源变化”。
3. UI 如果只显示笼统错误，会让玩家以为系统坏了，而不是知道如何恢复城市运转。
4. 前30秒 UI 必须克制，否则会遮挡第一次城市响应，破坏体素城市启动感。
5. 资源来源标注能防止任务奖励、商店购买、探索奖励与生产产出混淆。
6. 警告等级能防止红色危机滥用，避免把“待分配”“空闲”“等待住房”等正常前期状态吓人化。
7. UI 直接修改权威状态会破坏存档、联机、测试和回放，因此必须维持 Command / Simulation / ViewState 边界。
8. 本建议已访问仓库并确认当前暂存区没有相同主题，因此属于新的下一部分，而不是重复提交。
