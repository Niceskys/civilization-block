## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是为《文明块》的建筑放置合法性补充一套更清晰的“地形 / 地基 / 放置合法性”建议规则，用于解决后续设计回写和实现时可能出现的几个问题：

1. 小草、碎石、贴图颗粒等视觉细节不应让建筑难以放置。
2. 建筑合法性应以建造层、地基面、占地、承重、通行和地皮归属为准。
3. 建筑与高差地形之间应有地基、平台、支柱、挡墙等文明化过渡。
4. 新区块不应默认被完全铲平成平板，但也必须保证玩家有清楚可用的建造面。
5. 本轮只提供建议，不直接修改正式 A 级文档，也不修改 Runtime、存档结构、StateHash 或联机协议。

## 建议写入内容

待 Codex / 用户审核后回写。

建议未来在 `2.1 建筑通用规则.md` 的“首次合法放置的时间启动触发”之后，新增一个“地形、地基与放置合法性”小节。建议内容如下：

```md
#### 地形、地基与放置合法性

- 建筑放置合法性以建造层、地基面、占地、承重、通行、地皮归属和建筑自身限制为准。
- 地形颗粒仅作为视觉细节存在，包括草、碎石、小土坡、贴图起伏、边缘颗粒和泥土破碎感。
- 地形颗粒不得单独阻止建筑放置，也不得单独改变建筑成本、施工时长、承重、产出或维护规则。
- 建筑预览时，系统应显示建筑本体、占地范围、地基面和放置合法性结果。
- 合法位置显示绿色或青色虚影；非法位置显示红色虚影，并给出简短原因。
- 小草、碎石和极轻微颗粒起伏可在确认建造时自动清理、覆盖或压入地基表现，不额外增加成本。
- 轻微不平地形可自动找平，并生成薄地基边缘表现。
- 接近半层或一层的高差，需要通过地基、平台、支柱、挡墙、台阶或道路接驳表现来形成文明化过渡。
- 两层及以上高差，普通建筑不得直接放置，除非建筑自身属于桥、平台、支柱、高台、悬挑或其他专用结构。
- 水边、坑洞边、断崖边等特殊地形，需要桥基、木桩、填土、支撑或专用建筑规则，不得默认直接建造。
- 建筑不得直接裸压在明显高差形成的整面泥土柱上；可见高差必须有文明化过渡层。
- 本规则不新增整地成本、地基成本、平台成本或施工时长；如未来需要成本，必须先进入数值模拟表验证。
- 本规则不修改首次建造加速、免费重新放置、普通移动、拆除返还、Lv3自动运转、生产效率或同种建筑倍率。
```

建议未来在建造 UI 或实现任务中补充以下提示文案：

```md
- 位置不可建造：高差过大，需要先修建平台或支撑。
- 位置不可建造：建筑缺少稳定地基面。
- 位置不可建造：水边或坑洞边需要桥基、填土或专用结构。
- 位置可建造：轻微地形起伏将自动找平。
- 位置可建造：小型地形颗粒将自动清理或覆盖。
```

建议未来在实现任务中拆为以下检查项：

```md
- 检查建筑放置是否读取建造层，而不是读取每一个视觉颗粒。
- 检查地形颗粒是否只影响显示，不直接阻止建造。
- 检查高差是否能输出清楚的非法原因。
- 检查合法放置后是否能生成地基、平台、支柱或挡墙表现。
- 检查这些表现是否不改变资源产出和建筑效率。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 《文明块》的画面目标是“精细体素风”，需要草、碎石、边缘颗粒、小土坡等视觉细节；但如果这些视觉细节都参与阻挡判定，建造体验会变得非常难用。
2. 建筑系统需要一个清晰的规则层：玩家看到的地形可以精细，但程序判断必须稳定、可解释、可存档、可联机同步。
3. “建造层”和“地形颗粒”分离后，可以同时保留画面细节和操作清晰度。
4. 高差地形如果不处理，建筑会出现“上面是房子，下面是整面裸土柱”的违和感；文明化过渡层可以解决这一问题。
5. 本建议只限定规则边界，不引入新成本，避免提前扩大数值系统和 Runtime 实现复杂度。
6. 本建议有助于后续 Codex 实现时拆小任务，不会一次性重写建筑、地形、存档和渲染系统。
