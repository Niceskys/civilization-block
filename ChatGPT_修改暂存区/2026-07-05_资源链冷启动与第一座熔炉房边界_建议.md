## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是整理《文明块》前期资源链冷启动、第一座熔炉房、铁矿石 / 铁锭、燃料来源、任务奖励、商店交易之间的边界，避免后续出现循环依赖或伪造产出。

本建议的核心判断是：

> 第一座熔炉房应该开启加工时代，而不是要求玩家已经拥有加工时代的产物。

建议目标包括：

1. 避免第一座熔炉房建造成本需要铁锭，从而形成“没有熔炉不能炼铁、没有铁锭不能建熔炉”的循环锁。
2. 明确铁矿石、铁锭、燃料、木材、炭化、商店和任务奖励之间的前期边界。
3. 明确第一批铁矿石 / 铁锭可以有多种来源，但必须标注来源，不能伪造生产。
4. 明确树场应急炭化或类似机制只解决燃料冷启动，不应让木材直接替代所有燃料系统。
5. 明确任务奖励和商店交易可以缓解卡死，但不能成为唯一解法。
6. 明确资源链冷启动应先保证可玩闭环，再逐步引出地下探索、工具制造和专业生产。
7. 为 Codex 后续小步回写提供拆分顺序，避免一次性大改资源、建筑、商店、任务和地下系统。

## 建议写入内容

待 Codex / 用户审核后回写。

### 一、资源链冷启动总原则

建议未来在资源链或熔炉房相关文件中形成以下原则：

```md
### 资源链冷启动总原则

- 前期资源链必须避免循环依赖。
- 第一座用于开启某条生产链的建筑，不应要求该生产链的稳定产物作为建造前置。
- 第一座熔炉房用于开启铁锭加工，因此不应要求铁锭作为建造成本。
- 第二座及后续熔炉房可以逐步引入铁锭、工具或更高成本，但必须保证玩家已经存在可获得铁锭的路径。
- 冷启动资源可以来自基础采集、浅层探索、任务奖励、勘探奖励、商店交易或事件，但必须明确来源。
- 冷启动不得通过 UI、动画、任务文案或假产出伪造资源。
```

### 二、第一座熔炉房边界建议

```md
### 第一座熔炉房边界建议

- 每个存档的第一座熔炉房应使用冷启动成本，不要求铁锭。
- 冷启动成本可以以木材、石材、黏土、基础矿石、少量星辉或其他前期可获得资源为主。
- 第一座熔炉房可以要求铁矿石作为后续生产输入，但不应要求铁锭作为建造前置。
- 第一座熔炉房完成后，玩家才正式进入铁矿石 → 铁锭加工阶段。
- 第二座及后续熔炉房可以要求铁锭参与建造成本，用于体现工业化扩展。
- 第一座熔炉房被拆除或摧毁后，是否再次允许冷启动成本，需另行裁决，不得本轮直接定稿。
```

### 三、铁矿石来源建议

```md
### 铁矿石来源建议

- 第一批铁矿石可以来自浅层矿脉、地皮勘探、任务奖励、商店、随机事件或初始附近资源点。
- 不建议把第一批铁矿石完全绑定到深层地下探索。
- 不建议把第一批铁矿石完全绑定到商店购买。
- 不建议把第一批铁矿石完全绑定到任务奖励。
- 最稳妥的设计是允许至少两条获得路径，例如：浅层勘探 + 商店少量补货，或浅层矿点 + 任务少量奖励。
- 铁矿石的来源必须在 UI 或任务文案中明确标注，避免玩家误以为资源凭空出现。
```

### 四、铁锭来源建议

```md
### 铁锭来源建议

- 第一批铁锭原则上应由玩家通过第一座熔炉房加工铁矿石获得。
- 如果任务或商店提供少量铁锭，只能作为防卡死或引导用途，不应替代熔炉生产的核心地位。
- 不得要求玩家必须购买铁锭才能建造第一座熔炉房。
- 不得要求玩家必须完成任务领取铁锭才能建造第一座熔炉房。
- 铁锭作为更高阶段建材时，应在玩家理解熔炉生产后再广泛使用。
```

### 五、燃料冷启动建议

```md
### 燃料冷启动建议

- 熔炉房运行需要燃料，但第一轮燃料来源必须清楚、稳定、可理解。
- 树场应急炭化可以作为燃料冷启动方案之一。
- 应急炭化的作用是把前期木材来源转化为少量基础燃料，不是让木材永久替代完整燃料系统。
- 如果存在煤炭、木炭、焦炭、晶能燃料等多级燃料，应在后续阶段逐步展开。
- 第一座熔炉房不应因为玩家尚未理解完整燃料系统而无法启动。
- 燃料不足时，UI 应显示明确原因，例如“缺少燃料，可通过树场应急炭化获得”。
```

### 六、商店防卡死边界建议

```md
### 商店防卡死边界建议

- 商店可以提供少量冷启动资源，用于防止玩家因误操作或资源耗尽卡死。
- 商店不得成为第一座熔炉房冷启动的唯一解法。
- 商店出售铁矿石、铁锭、燃料或工具时，应控制数量、价格和出现阶段。
- 商店补货应服务防卡死和策略选择，不应替代生产链。
- 随机商人可以提供临时缓解，但不得作为主线必需节点。
- 如果玩家完全不使用商店，也应存在通过探索、采集或生产获得冷启动资源的路径。
```

### 七、任务奖励边界建议

```md
### 任务奖励边界建议

- 任务可以奖励少量铁矿石、燃料或辅助资源，用于引导玩家进入熔炉链。
- 任务奖励不得伪装成建筑生产产出。
- 任务奖励不得成为建造第一座熔炉房的唯一必要来源。
- 任务奖励可以用于缓解第一次熔炉生产输入不足，但不应替代熔炉房的核心功能。
- 任务系统应记录玩家首次炼出铁锭，而不是提前把铁锭作为必须领取的门票。
```

### 八、第一座熔炉房 UI 反馈建议

```md
### 第一座熔炉房 UI 反馈建议

- 熔炉房详情应清楚显示：输入资源、燃料需求、输出资源、当前等待原因。
- 第一座熔炉房完成后，应显示“可加工铁矿石为铁锭”的清楚提示。
- 输入不足时显示“缺少铁矿石”。
- 燃料不足时显示“缺少燃料”。
- 工人不足时显示“待分配工人”或“无人工作”。
- 产物满仓时显示“产物待转移”。
- 不得用笼统的“停产”或“错误”替代具体原因。
```

### 九、冷启动异常处理建议

```md
### 冷启动异常处理建议

- 如果玩家消耗完全部冷启动资源，应至少存在一种恢复路径。
- 恢复路径可以是浅层资源点、低频商店补货、任务补救、勘探奖励或基础事件。
- 恢复路径不应破坏生产链，也不应无限免费刷资源。
- 第一座熔炉房如果取消施工、施工失败或被摧毁，冷启动资格是否恢复需单独裁决。
- 如果冷启动成本使用实际支付快照，拆除返还仍应遵守正式拆除规则，不得产生额外资源。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 第一座熔炉房是资源链从基础生存进入加工生产的重要节点，如果成本设计错误，会直接造成循环锁。
2. 要求第一座熔炉房消耗铁锭，会形成“没有熔炉就没有铁锭，没有铁锭就没有熔炉”的典型冷启动问题。
3. 商店和任务奖励可以防卡死，但如果变成唯一解法，会削弱经营建造和生产链的核心体验。
4. 燃料系统如果太复杂，会过早压垮新手；如果太简单，又会让后续燃料链失去价值，因此需要冷启动与长期燃料分层。
5. 铁矿石 / 铁锭链应与地下探索、工具制造、熔炉房、任务、商店保持一致，不应在多个文件中互相矛盾。
6. UI 必须告诉玩家缺的是铁矿石、燃料、工人还是仓储，而不是笼统地显示停产。
7. 本建议作为暂存文件，可以让 Codex / 用户先审查资源链方向，再逐文件小步回写，避免一次性修改多个正式源文件。
