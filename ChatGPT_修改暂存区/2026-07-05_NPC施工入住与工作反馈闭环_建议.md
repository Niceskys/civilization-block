## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是整理《文明块》前期 NPC 在“城市开始运转”中的表现、规则边界和 UI 反馈，避免后续出现两类相反问题：

1. NPC 只有数值，不参与玩家第一次城市响应，导致城市像空壳。
2. NPC 过早制造饥饿、恐惧、缺工、无房、停产等危机，导致玩家还没完成基础闭环就被惩罚。

本轮希望将 NPC 在前期的角色固定为：

> 开局阶段，NPC 首先负责让城市“活起来”；等基础闭环建立后，再逐步承担生产、分工、记忆、情绪、职业和危机压力。

建议目标包括：

1. 明确第一次建筑放置前，NPC 可以表现存在感，但不制造惩罚。
2. 明确第一次施工任务创建后，NPC 应优先进入施工反馈。
3. 明确第一座房屋完成后，NPC 自动入住反馈应帮助玩家理解住房系统。
4. 明确生产建筑完成后，“待分配 / 空闲 / 可工作”应比红色危机更适合前期。
5. 明确 NPC 表现层只解释权威状态，不直接决定资源、生产或任务结果。
6. 明确 NPC 早期反馈应与任务、UI、建筑、时间系统和前30秒体验统一。

## 建议写入内容

待 Codex / 用户审核后回写。

### 一、NPC 前期角色总原则

建议未来在 NPC 或前期体验相关文件中形成以下原则：

```md
### NPC 前期角色总原则

- 新存档前期，NPC 的第一作用是让城市产生生命感和响应感。
- NPC 不应在玩家第一次合法建筑放置前制造资源消耗、恐惧危机、无房惩罚、缺工惩罚或随机负面事件。
- NPC 可以在初始地皮上待机、短距离走动、观察文明核心、看向玩家操作方向或表现等待状态。
- NPC 的早期表现应帮助玩家理解：这里不是空地图，而是一座等待启动的城市。
- NPC 的正式生产、职业、情绪、好感、恐惧和社交系统应在基础城市闭环建立后逐步展开。
```

### 二、第一次建筑放置前的 NPC 状态

```md
### 第一次建筑放置前的 NPC 状态

- 新存档进入后，NPC 可以显示为等待、闲置、观察、聚集在文明核心附近或进行低频移动。
- 该阶段 NPC 不应主动消耗关键资源导致玩家开局惩罚。
- 该阶段 NPC 不应因为没有房屋而立刻触发严重负面状态。
- 该阶段 NPC 不应因为没有工作岗位而显示红色危机。
- UI 可以显示“等待建设”“尚未分配工作”“等待第一座建筑”等温和状态。
- 玩家观察、旋转视角、打开面板或犹豫时，NPC 不应把等待时间转化为惩罚。
```

### 三、第一次施工任务创建后的 NPC 响应

```md
### 第一次施工任务创建后的 NPC 响应

- 玩家第一次合法确认建筑放置并创建施工任务后，应优先触发 NPC 施工响应。
- 如果存在可用成年 NPC，至少一名 NPC 应进入施工相关表现。
- 施工表现可以包括：走向工地、搬运材料、敲打建筑框架、站在施工点附近工作、短循环施工动画。
- NPC 施工表现不需要复杂 AI，但必须让玩家看懂城市开始动起来。
- 如果没有可用工人，应显示温和原因，例如“暂无可施工 NPC”“等待工人”，不得直接显示严重失败。
- NPC 施工动画只解释施工任务状态，不直接决定施工完成；施工完成仍由正式施工任务和时间规则决定。
```

### 四、第一座房屋完成后的入住反馈

```md
### 第一座房屋完成后的入住反馈

- 第一座房屋完成后，如果存在符合条件的 NPC，应优先展示自动入住反馈。
- 入住反馈可以包括：NPC 走入房屋、房屋窗口亮起、床位状态变化、房屋详情出现住户、底栏轻提示。
- 自动入住排序、候选条件和床位分配仍应遵守正式住房规则。
- 婴儿是否占床、夫妻 / 家庭关系、住房偏好等复杂规则不应在第一座房屋完成瞬间强制展示。
- 第一座房屋完成后，不应立刻用红色警告强调“住房不足”，除非正式规则确认存在严重问题。
- 如果房屋床位已满或没有符合条件 NPC，应显示中性提示，不应误报系统错误。
```

### 五、基础生产建筑完成后的工作反馈

```md
### 基础生产建筑完成后的工作反馈

- 第一座农田、水井、树场等基础生产建筑完成后，应显示“可工作 / 待分配 / 空闲 / 缺少工人”中的温和状态。
- 前期“缺少工人”不应默认显示为红色危机，除非该状态已经造成明确损失或长期停摆。
- 若玩家尚未打开 NPC 管理或工作分配界面，应通过轻提示引导，不强制弹窗。
- 生产建筑详情应显示工位、当前状态、是否已分配 NPC、缺少输入 / 缺少工人 / 产物待转移等基础原因。
- 建筑完成后如果暂时无人工作，应让玩家知道“建筑已经可用，只是还需要分配或等待 NPC”。
- 不得因为 UI 没刷新而让生产建筑进入错误停产或重复分配状态。
```

### 六、NPC 管理 UI 早期显示建议

```md
### NPC 管理 UI 早期显示建议

- 前期 NPC UI 应优先显示少量核心信息：姓名 / 状态 / 住房 / 当前工作 / 是否空闲。
- 不应在前30秒强制展示完整职业、好感、恐惧、社交、记忆、性格专长等复杂面板。
- NPC 空闲状态应使用中性表达，例如“空闲中”“等待任务”“暂无岗位”。
- NPC 无房状态在第一座房屋完成前应避免强红警告，可显示“等待住房建设”。
- NPC 未分配工作时，应提供明确入口，但不强制玩家立即处理。
- 早期 NPC 管理 UI 应帮助玩家理解城市，而不是制造管理压力。
```

### 七、任务系统与 NPC 里程碑建议

```md
### NPC 相关早期里程碑建议

- 任务系统可以记录第一次 NPC 参与施工。
- 任务系统可以记录第一位 NPC 入住房屋。
- 任务系统可以记录第一次给 NPC 分配工作。
- 任务系统可以记录第一座生产建筑开始运转。
- 这些里程碑应作为记录和轻提示，不得成为建筑、入住、工作分配或生产的前置条件。
- 玩家通过自由操作提前完成相关行为时，任务应能自动识别完成。
```

### 八、表现层与权威状态边界建议

```md
### NPC 表现层边界

- NPC 动画、走路、施工动作、入住动作、表情和 UI 状态只解释权威状态。
- NPC 表现层不得直接修改资源、建筑、床位、岗位、生产进度、任务完成或时间状态。
- 如果玩家点击 NPC 或 UI 触发操作，必须转化为正式 Command，再由 Simulation 校验。
- 关闭 NPC 细节动画、降低画质或隐藏部分状态图标，不得改变 NPC 工作、入住或生产结果。
- NPC 寻路表现失败不等于权威任务失败，除非正式寻路 / 任务系统确认该任务失败。
```

### 九、前期危机延迟建议

```md
### 前期危机延迟建议

- 在第一次合法建筑放置前，不建议触发 NPC 饥饿、恐惧、无房、缺工、社交冲突等惩罚性危机。
- 在第一座建筑完成前，不建议把 NPC 空闲、无岗位、无房直接显示为红色危机。
- 前期危机更适合在玩家已经拥有基本操作理解后逐步出现。
- 若必须提示风险，应采用温和预告，例如“居民正在等待住房”“有人空闲，可分配工作”。
- 不得让 NPC 系统在玩家理解基础建造前成为失败来源。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 《文明块》不是纯建筑摆放游戏，NPC 是城市生命感的重要来源；如果前期 NPC 没反应，第一次建造反馈会变弱。
2. 但 NPC 系统又不能过早变成压力源，否则玩家在理解房屋、农田、水井、树场之前就会被一堆红色状态吓退。
3. NPC 施工、入住、工作反馈是前30秒体验和基础城市闭环的关键连接点。
4. 自动入住规则已经有严格候选条件和排序，前期 UI 需要把它表现出来，而不是让玩家感觉 NPC 是随机消失或凭空住进去。
5. 生产建筑完成后的“待分配 / 空闲”提示，比“停产 / 危机 / 错误”更符合新手阶段。
6. NPC 表现层必须与 Simulation 权威状态分离，否则后续存档、联机、调试和测试会变得混乱。
7. 把 NPC 反馈规则先写成暂存建议，可以避免直接大改 `3.1`、`3.3`、`5.4` 等正式文件。
8. 该主题与基础城市闭环、前30秒留存边界、表现层边界、任务系统早期里程碑高度相关，适合作为完整主题包处理。
