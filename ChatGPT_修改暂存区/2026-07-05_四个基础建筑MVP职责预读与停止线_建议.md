## 总体判断

待 Codex / 用户审核后回写。

四个基础建筑文件总体适合后续小步回写，但必须采用“新增 MVP 职责与停止线”的方式，而不是重写原有建筑详情。

总体结论：

1. 房屋最稳定，已有居住容量、自动入住、床位排序等规则，适合直接补充“MVP 职责”。
2. 农田是风险最高的基础建筑之一，因为文件中已有光照、太阳灯、燃料覆盖、施肥等 Runtime 规则；MVP 不能把这些全部当作首版必做。
3. 水井结构最简单，适合直接补充“MVP 职责”；但水井当前建造成本为 10 石头，与 MVP 资源闭环“木材/食物/水/人口/空闲工人”之间存在冷启动风险，后续需要由 6.1 或 MVP 初始资源裁决解决。
4. 树场是另一个风险点，因为已有“应急炭化”与燃料链规则；MVP 必须只吸收可再生木材职责，不能把燃料 / 应急炭化拉入第一版。
5. 四个建筑都包含升级到 Lv2~Lv4 和铁锭等中后期成本；MVP 只需要 Lv1 可运行，不应要求升级链进入 MVP。

建议后续正式回写时，每个文件只新增一个小节：

```md
### MVP 职责与停止线
```

该小节放在 `### 快速摘要` 之后，具体机制章节之前。

### 1. 房屋

#### 现有内容

房屋文件已有：

- 初始解锁。
- 建造成本 10 木材。
- 建造时长 0.5 游戏日。
- 首次房屋施工加速。
- Lv1 居住容量 2 床位。
- 无工人。
- 耐久、承重、升级。
- 自动入住结算。
- NPC 创建顺序分配床位。
- 空床位按房屋创建序号与床位槽位序号分配。
- 不驱逐、不交换、不重排已有住户。
- 玩家手动分配优先保留。
- 房屋失效后住户失去床位并尝试迁入其他有效空床。
- 房屋不负责自动分配职业或工作建筑。

#### MVP 判断

房屋是四个基础建筑中最适合进入 MVP 的建筑。

MVP 必须吸收：

- Lv1 提供 2 床位。
- 房屋完成后触发自动入住结算。
- 房屋提供居住容量和人口稳定反馈。
- 房屋只负责居住，不负责工作分配。

MVP 不需要吸收：

- Lv2~Lv4 升级链。
- 铁锭相关升级成本。
- 家庭关系。
- 生育系统。
- 舒适度系统。
- 情绪 / 社交 / 个体记忆。
- 完整室内模拟。

#### 建议写入小节

```md
### MVP 职责与停止线

房屋在 MVP 中承担居住容量、自动入住反馈和人口稳定入口。

MVP 必须保证：
- Lv1 房屋提供有效床位。
- 房屋完成施工后能够触发一次自动入住结算。
- 建筑详情或相关 UI 能显示床位占用状态。
- 无床位 NPC 可以被解释为等待住房或无家可归。
- 房屋只负责居住，不负责工作或职业分配。

MVP 不要求实现：
- 家庭关系。
- 生育。
- 舒适度。
- 情绪、社交、好感度、记忆。
- 完整房屋内部模拟。
- 房屋升级链。
```

#### 风险

风险较低。

注意不要在 MVP 中要求完整家庭 / 生育 / 室内系统。

### 2. 农田

#### 现有内容

农田文件已有：

- 初始解锁。
- 建造成本 5 木材 + 1 水。
- 建造时长 1 游戏日。
- 首次基础生产建筑加速。
- 运行消耗 1 水 / 日。
- 工人上限 2。
- 基础产出 4 食物 / 工人 / 游戏日。
- 耐久、承重、升级。
- 光照规则。
- 正上方遮挡停产。
- 太阳灯覆盖恢复夜间 / 遮挡生产。
- Runtime 光照规则。
- 太阳灯燃料覆盖进入存档、StateHash 和服务器权威快照。
- Runtime 施肥规则。

#### MVP 判断

农田进入 MVP，但必须裁剪。

MVP 必须吸收：

- 农田消耗水。
- 农田需要工人。
- 农田周期产出食物。
- 农田可显示等待原因，例如缺水、缺工人、暂停中。

MVP 暂不应吸收为必做：

- 太阳灯系统。
- 夜间光照恢复。
- 遮挡完整裁决。
- 燃料覆盖。
- StateHash 光照覆盖。
- 服务器权威快照。
- 施肥系统。
- 多作物、季节、病虫害、土壤肥力。
- 农田升级链。

#### 建议写入小节

```md
### MVP 职责与停止线

农田在 MVP 中承担基础食物来源。

MVP 必须保证：
- 农田可以消耗水并周期产出食物。
- 农田至少需要基础工位或有效劳动力参与。
- 农田在缺水、缺工人或建筑不可运行时显示明确等待原因。
- 农田产出属于真实生产结果，不得由任务、商店或 UI 伪造。

MVP 不要求实现：
- 完整光照遮挡系统。
- 太阳灯恢复生产。
- 太阳灯燃料覆盖。
- 施肥系统。
- 多作物、季节、病虫害、土壤肥力。
- 农田升级链。

现有光照、太阳灯、燃料覆盖、施肥等规则保留为后续扩展，不作为 MVP 第一版必做。
```

#### 风险

风险高。

农田文件已有大量 Runtime 光照和施肥规则。后续正式回写时，必须明确这些是后续扩展，不得让 Codex 把太阳灯、燃料、StateHash 和服务器权威当成 MVP 必做。

### 3. 水井

#### 现有内容

水井文件已有：

- 初始解锁。
- 建造成本 10 石头。
- 建造时长 1 游戏日。
- 首次基础生产建筑加速。
- 工人上限 2。
- 产出 4 水 / 工人 / 游戏日。
- 无运行消耗。
- 耐久、承重、升级。
- 水井产出进入全局水库存。
- NPC 每日消耗 0.5 水 / 人。
- 农田灌溉消耗额外水。

#### MVP 判断

水井必须进入 MVP，作为基础水来源。

MVP 必须吸收：

- 水井产水。
- 水进入全局水库存或等价的城市水状态。
- 水支撑 NPC 生存消耗和农田灌溉。
- 水井需要工人或有效劳动力参与。
- 缺工人时显示等待原因。

MVP 暂不应吸收为必做：

- 水井升级链。
- Lv3 自动运转。
- 地下水位。
- 水质。
- 污染。
- 水桶物流。
- 井深升级。
- 地下探索联动。

#### 冷启动风险

水井当前建造成本为 10 石头，而 MVP 主循环建议只强调木材、食物、水、人口、空闲工人。

这会产生一个需要后续裁决的问题：

- 如果 MVP 玩家一开始没有石头，水井无法建造，水循环无法启动。
- 如果 MVP 还不引入采掘场或石头生产，必须通过初始资源、数值表特殊成本或 MVP 首轮规则解决。

建议后续不要在本文件中直接改成本；成本权威应由 `6.1 建筑数值表` 维护。这里只记录风险。

#### 建议写入小节

```md
### MVP 职责与停止线

水井在 MVP 中承担基础水来源。

MVP 必须保证：
- 水井能够产出水。
- 水能够进入城市水库存或等价水状态。
- 水可用于 NPC 生存消耗与农田灌溉。
- 水井在缺工人或不可运行时显示明确等待原因。

MVP 不要求实现：
- 水井升级链。
- 自动运转。
- 地下水位。
- 水质和污染。
- 水桶物流。
- 井深升级。
- 地下探索联动。

注意：水井建造成本由 6.1 维护。若 MVP 不引入石头生产，需通过初始资源或数值表裁决解决水井冷启动问题。
```

#### 风险

中高风险。

最大风险不是机制复杂，而是建造成本冷启动。如果第一版 MVP 没有石头来源，水井可能成为基础闭环断点。

树场文件已有：

- 建造成本 10 木材。

- 树场让城市可以继续扩张，而不是只依赖初始木材。
- 树场可显示运行 / 等待工人 / 产木反馈。

MVP 暂不应吸收为必做：

- 应急炭化。
- 燃料链。
- 垃圾处理场联动。
- 熔炉房 / 太阳灯缺燃料响应。
- 工具效率链。

## 冲突与风险汇总

待 Codex / 用户审核后回写。

### 风险 1：水井建造成本与 MVP 资源子集冲突

水井当前建造成本为 10 石头，但 MVP 主循环强调木材、食物、水、人口、空闲工人。若 MVP 不引入石头来源，水井可能无法建造。

建议：

- 不在水井文件直接改成本。
- 后续在 `6.1 建筑数值表` 或 MVP 初始资源裁决中解决。
- 可以采用初始资源包含石头、MVP 水井特殊成本、或初始水井预置等方案，但需另行裁决。

### 风险 2：农田光照 / 太阳灯 / 燃料 / StateHash 过早进入 MVP

农田文件已写入 Runtime 光照、太阳灯燃料覆盖、StateHash、服务器权威快照等内容。

建议：

- 第一批只写农田 MVP 需要水、工人、产食物和等待原因。
- 光照、太阳灯、燃料覆盖、施肥保留为后续扩展。

### 风险 3：树场应急炭化拖入燃料链

树场文件已有应急炭化规则，容易把燃料、垃圾处理场、熔炉房、太阳灯带进 MVP。

建议：

- 第一批只写树场可再生木材职责。
- 应急炭化明确不作为 MVP 第一版必做。

### 风险 4：房屋自动入住与完整 NPC 生活模拟混淆

房屋已有自动入住和无家可归规则，适合 MVP，但不能继续扩展成家庭、生育、舒适度、情绪等系统。

建议：

- MVP 只保留床位、自动入住、居住容量反馈。
- 复杂 NPC 生活系统延后。

### 风险 5：升级链带入铁锭和中后期系统

四个文件都含升级链，其中常见 Lv3 / Lv4 涉及铁锭等中后期资源。

建议：

- MVP 只要求 Lv1。
- 升级链保留为长期规则，不作为 MVP 第一版完成标准。
