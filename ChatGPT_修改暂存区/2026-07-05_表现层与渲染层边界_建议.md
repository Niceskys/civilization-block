## 本轮目标

待 Codex / 用户审核后回写。

本轮目标是为《文明块》的 Runtime 架构和视觉实现补充“表现层 / 渲染层边界”建议，避免后续实现时把 Shader、灯光、动画、粒子、UI 或摄像机效果误做成权威游戏状态。

本轮只提出建议，不修改正式 A 级文档，不修改 Runtime，不修改存档结构，不修改 StateHash，不修改联机协议。

建议目标包括：

1. 明确 Simulation Layer 才是资源、建筑、NPC、时间、任务、生产、战斗等系统的权威来源。
2. 明确表现层、渲染层、动画、灯光、粒子、UI 和摄像机只读取权威状态或 ViewState。
3. 明确降低画质、关闭粒子、关闭内部视角或隐藏装饰细节，不得改变游戏结果。
4. 为未来 Unity + C# + URP + 自定义体素风 Shader + 分层渲染实现提供边界。
5. 降低后续 Codex 实现时“画面效果反向影响模拟”的风险。

## 建议写入内容

待 Codex / 用户审核后回写。

建议未来在 `00.5 Runtime架构蓝图_v1.md` 中新增一个“表现层、渲染层与权威状态边界”小节。建议内容如下：

```md
### 表现层、渲染层与权威状态边界

- Simulation Layer 是游戏权威状态来源。
- 资源、建筑、NPC、时间、任务、生产、战斗、事件、存档、联机同步等结果必须由 Simulation Layer 或其正式命令 / 事件系统决定。
- 表现层、渲染层、动画、Shader、灯光、粒子、音效、UI 和摄像机不得直接修改权威游戏状态。
- 表现层只能读取 Simulation Layer 派生出的 ViewState、PresentationState 或事件流。
- ViewState 可以缓存显示所需数据，但不得成为资源、建筑、NPC、生产、战斗或任务结果的唯一来源。
- 降低画质、关闭粒子、隐藏装饰、关闭内部视角、关闭动态阴影或切换摄像机，不得改变游戏模拟结果。
- 如果表现层需要触发玩家操作，必须转化为正式 Command，再由 Simulation Layer 校验后执行。
- UI 按钮、快捷键、建造预览确认、内部视角点击等输入，不得绕过 Command 校验直接改写建筑或资源。
```

建议未来在技术实现任务中采用以下分层：

```md
- Simulation Layer：权威模拟、命令、事件、存档、联机一致性。
- ViewState Layer：由权威状态派生出的显示状态缓存。
- Presentation Layer：动画、状态灯、建筑内部视角、粒子、音效、UI 展示。
- Rendering Layer：URP、Shader、材质、光照、阴影、后处理、体素 AO。
- Input Layer：玩家输入转化为 Command，不直接修改游戏状态。
```

建议未来在代码任务中加入以下检查项：

```md
- 搜索渲染、UI、动画、粒子脚本中是否直接写资源、建筑、NPC 或时间状态。
- 检查 Shader 参数是否只读取显示状态，不反向影响生产效率。
- 检查 UI 按钮是否发送 Command，而不是直接修改 Simulation 数据。
- 检查内部视角关闭后，生产、入住、库存、任务进度是否保持一致。
- 检查低 / 中 / 高画质切换后，模拟结果是否完全相同。
- 检查窗口暖光、熔炉火光、工坊火花是否只解释状态，不决定状态。
```

建议未来在测试或人工验收中加入以下样例：

```md
- 同一存档在低画质和高画质下运行同样时间，资源结果应一致。
- 关闭建筑内部视角后，房屋入住、工坊生产、熔炉运行不应改变。
- 关闭粒子后，建造完成、资源产出、NPC工作状态不应改变。
- 关闭动态光影后，怪物、恐惧、生产、任务不应改变。
- UI 面板刷新失败时，不应导致权威资源数值丢失或重复生成。
```

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 《文明块》未来会包含体素建筑、窗口暖光、熔炉发光、工坊火花、内部视角、体素 AO、状态提示等大量表现效果，如果边界不清，容易让表现层和模拟层混在一起。
2. 表现层一旦能直接修改资源、生产、NPC 或任务状态，后续存档、联机、回放、调试和测试都会变得不稳定。
3. 画质分档必须只影响表现，不能影响游戏难度或模拟结果，否则低配玩家和高配玩家会出现不同游戏逻辑。
4. 内部视角属于高成本表现层，不能成为生产运转的必要条件，否则关闭内部视角会破坏玩法。
5. 明确 Command / Simulation / ViewState / Presentation / Rendering 的边界，可以让 Codex 后续小步实现，减少一次性重构风险。
6. 该建议与当前“Unity + C# + URP + 自定义体素风 Shader + 分层渲染 + 画质分档”的方向一致，但不会直接扩大 Runtime 实现范围。
