## 建议任务 S4：`2.1 建筑通用规则.md`

### 文件现状

该文件已定稿，已有建造资源消耗、施工时长、工人参与、首次合法放置触发时间、新存档首次建造加速、预约 / 消耗 / 取消 / 存档、耐久、维修、拆除、升级等严格规则。

### 主要风险

不能在这里重写建筑流程，也不能破坏已有首建加速和存档规则。

### 建议小改方向

建议在 `### 建造规则` 后、`#### 首次合法放置的时间启动触发` 前补充：

```md
#### MVP 基础建筑启用子集

MVP 第一版只要求以下四类建筑进入基础城市主循环：

- 房屋；
- 农田；
- 水井；
- 树场。

这些建筑分别承担居住容量、食物来源、水来源和可再生木材来源。

其他建筑可以存在于完整设计中，但不作为 MVP 第一版主循环必做内容。

MVP 建筑仍然遵守本文件既有的放置、施工、首次时间启动、首建加速、资源消耗、取消、失败、存档与读档规则。

MVP 阶段不得因为完整设计中存在熔炉房、采掘场、商店、地下入口、工具工坊、科技建筑、防御建筑，就把它们写成第一版必须建造或必须运行的建筑。
```

### 禁止事项

- 不重写首建加速规则。
- 不改存档字段。
- 不新增熔炉、矿场、商店、地下入口为 MVP 必建建筑。
- 不在本批展开完整地形 / 地基 / 承重数据模型。

## 建议任务 S5：`3.3 工作分配逻辑.md`

### 文件现状

该文件已定稿，已有权威边界、Runtime 最小岗位契约、工作分配方式、硬性条件、分配事务、自动分配边界、工人与岗位、夜班、属性适配、NPC 死亡、多职业多阶段工作循环等内容。

### 主要风险

MVP 闭环需要“空闲 NPC 参与施工 / 基础生产”，但现有规则明确系统不得自动替玩家确认正式岗位分配。这里存在潜在冲突。

### 建议小改方向

建议在 `### Runtime最小岗位契约` 后补充：

```md
### MVP 劳动力启用子集

MVP 第一版中，NPC 的作用是让城市基础闭环真实运转，但不启用完整人生模拟。

MVP 必须真实保留：

- 人口数；
- 空闲 / 占用工人；
- 施工参与；
- 基础生产岗位占用；
- 房屋入住状态；
- 城市级食物 / 水消耗；
- 建筑运行或等待原因中的工人状态。

MVP 不要求启用：

- 职业成长；
- 情绪；
- 恐惧；
- 社交；
- 好感度；
- 个体记忆；
- 完整路径驱动生产结算；
- 个体吃饭喝水行为；
- 个体生命周期细节；
- 家庭关系；
- 多阶段职业动画完整闭环。

MVP 中的“空闲 NPC 参与施工 / 基础生产”不得绕过本文件的岗位权威边界。

若实现为自动响应，应限定为施工参与、空闲杂活或 MVP 临时劳动力响应，不等于系统自动替玩家确认正式岗位分配。

正式岗位分配、换岗和解除仍应遵守本文件既有的确认、事务和权威状态规则。
```

### 禁止事项

- 不删除自动分配边界。
- 不删除 Runtime 最小岗位契约。
- 不把职业、夜班、恐惧、死亡、工作循环细节写成 MVP 必做。
- 不让 UI 临时模拟岗位权威状态。

## 建议任务 S6：`5.1 全局界面.md`

### 文件现状

该文件已有完整 UI：顶部资源栏、快捷功能区、商店、任务、NPC 列表、科技、挑战、贸易路线、事件日志、设置、存档、时间控制、悬浮面板、城市脉搏条、数据仪表盘等。

### 主要风险

不能把完整 UI 删除成 MVP UI，也不能让商店、任务、科技等入口干扰前30秒。

### 建议小改方向

建议在 `## 游戏主界面元素` 后、`### 顶部资源栏（可自定义）` 前补充：

```md
### MVP 首屏启用子集

本文件维护完整 UI 规划。MVP 第一版只启用其中的首屏最小子集，不代表删除长期 UI 入口。

MVP 首屏至少需要：

- 木材；
- 食物；
- 水；
- 人口；
- 空闲工人；
- 时间 / 暂停状态；
- 建造入口；
- 一个非强制轻量下一步提示。

商店、任务、科技、挑战、贸易路线、事件日志、数据仪表盘等入口可以属于完整 UI 规划，但不得在新存档前30秒自动打开，不得强制引导，不得遮挡第一座建筑放置。

MVP UI 的职责是解释状态和下一步，不得伪造资源产出，不得自行修改 Runtime 权威状态。
```

### 禁止事项

- 不删除完整快捷功能区。
- 不删除城市脉搏条规则。
- 不让 UI 自行计算 Runtime 诊断。
- 不引入红点、签到、商店促销或任务强制引导。

## 建议任务 S7：`5.2 建造系统 UI.md`

### 文件现状

该文件已有完整建造 UI：五个一级 Tab、建筑卡层级、搜索、筛选、当前任务推荐、免费重新放置、首建加速、分类教程节点、存档与异常恢复、升级交互。

### 主要风险

不能把完整建造 UI 改成只有四张建筑卡。四张基础建筑应该作为 MVP 首轮可见子集，而不是永久替代建造系统。

### 建议小改方向

建议在 `### 建造面板` 后、`### 建造面板一级分类` 前补充：

```md
### MVP 首轮建造卡子集

MVP 第一版首轮建造面板必须保证玩家能看到并选择以下四张基础建筑卡：

- 房屋；
- 农田；
- 水井；
- 树场。

房屋可以显示“推荐”标签，但不得锁定其他三类基础建筑选择。

四张基础建筑卡至少应显示：建筑名称、简短用途、建造成本、当前是否可建、不可建原因。

完整的五个一级 Tab、搜索、筛选、未解锁折叠、任务推荐、收藏、最近使用等机制属于长期建造 UI 规划，不因 MVP 子集而删除。

前30秒不得自动切换 Tab、不得自动选择建筑、不得自动确认建造、不得因教程展示而扣除资源或创建施工任务。
```

### 禁止事项

- 不删除五个一级 Tab。
- 不删除免费重新放置、首建加速、分类教程和存档恢复规则。
- 不把当前任务推荐作为第一座建筑前置条件。
- 不新增“全部”“推荐”“临时活动”等一级 Tab。

## 建议任务 S8：`5.3 建筑详情 UI.md`

### 文件现状

该文件已有完整建筑详情 UI：建筑内部小窗、全屏切入、多分区内部空间、17 种建筑多分区和交互点、房屋床位面板、生产效率、升级、移动、拆除、专业化效率拆解、高度分区反馈等。

### 主要风险

该文件与 MVP 裁剪冲突较明显。MVP 不应要求完整建筑内部视图、17 种建筑分区和手动交互点。

### 建议小改方向

建议在 `# 建筑详情UI（通用规范）` 后、`### 面板打开与关闭` 前补充：

```md
## MVP 建筑详情启用子集

本文件维护完整建筑详情 UI 规划。MVP 第一版只启用其中的最小状态解释子集。

MVP 建筑详情 UI 至少显示：

- 建筑名称；
- 当前状态；
- 施工 / 运行 / 暂停；
- 工位状态；
- 输入资源；
- 输出资源；
- 等待原因；
- 可用 / 不可用原因。

MVP 建筑详情 UI 不得只显示“停产”或“错误”，必须尽量给出可理解原因，例如缺水、缺工人、施工中、缺输入、产物待转移、建筑不可运行。

建筑内部小窗、全屏切入、多分区交互、手动操作点、17 种建筑完整内部视图、专业化效率完整拆解和高度分区收益，不作为 MVP 第一版必做。

房屋床位面板可以作为 MVP 房屋反馈的一部分，但不得要求完整室内模拟。
```

### 禁止事项

- 不删除现有内部视图长期规划。
- 不把完整内部视图写成 MVP 必做。
- 不把熔炉、采掘场、太阳灯、工坊等建筑详情写入 MVP 必做。
- 不让 UI 面板直接修改建筑、资源、NPC 或生产权威状态。
