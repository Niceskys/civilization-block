## 三、后续候选同步文件与边界

### 1. `文明块/05-UI 与交互设计/5.1 全局界面.md`

只建议同步：

- UI / View 只能读取 Runtime 输出。
- UI / View 只能向 Runtime 提交 Command。
- 全局界面展示应以 Runtime State / Event / Diagnostics 等输出为准。

不应修改或扩展：

- 不得复制 Runtime 算法。
- 不得维护第二套诊断优先级。
- 不得把 UI 显示逻辑写成权威规则。
- 不得让 UI 直接修改权威 State。

### 2. `文明块/05-UI 与交互设计/5.2 建造系统 UI.md`

只建议同步：

- 建造 UI 只能构造 Command。
- 建造 UI 的职责是表达玩家意图、提交建造请求、展示 Runtime 返回结果。
- 建造 UI 应通过 CommandBus / Simulation 进入权威裁决链路。

不应修改或扩展：

- 不得直接扣资源。
- 不得直接创建建筑。
- 不得直接推进施工。
- 不得绕过 CommandBus / Simulation。
- 不得新增建造玩法或建筑放置规则。

### 3. `文明块/05-UI 与交互设计/5.3 建筑详情 UI.md`

只建议同步：

- 建筑详情 UI 读取 Runtime State / Event / Diagnostics。
- 建筑详情 UI 只展示 Runtime 已输出的建筑状态、诊断、事件和可读字段。
- 建筑详情 UI 可展示结构化诊断字段，但不应把展示文案当作规则来源。

不应修改或扩展：

- 不得自行计算生产。
- 不得自行计算库存。
- 不得自行计算物流。
- 不得自行计算承重。
- 不得自行计算光照。
- 不得自行计算燃料。
- 不得自行计算消耗。
- 不得解析自然语言 Message 作为规则来源。
- 不得维护 UI 侧第二套建筑运行规则。

### 4. `文明块/02 - 建筑系统/2.1 建筑通用规则.md`

只建议同步：

- 建筑放置必须进入 Command / Simulation。
- 建筑施工必须进入 Command / Simulation。
- 建筑拆除必须进入 Command / Simulation。
- 建筑岗位分配必须进入 Command / Simulation。
- 建筑生产裁决必须进入 Command / Simulation。
- 建筑相关规则应明确 Runtime 是权威执行边界，UI、网络层和外部工具不得绕开该边界直接改 State。

不应修改或扩展：

- 不得新增玩法。
- 不得改建筑数值。
- 不得改水井成本。
- 不得改 `6.1` 数值表。
- 不得在通用规则中提前写入尚未裁决的新系统。

### 5. `文明块/00 - 项目总纲/00.24 三维占地与房间模块迁移设计_v1.md`

只建议同步：

- 三维占地必须由 Runtime 权威系统计算。
- 支撑必须由 Runtime 权威系统计算。
- 通行必须由 Runtime 权威系统计算。
- 占用、碰撞、承重、连通、房间边界等结果应由 Runtime 输出给 UI / View / 网络层读取。

不应修改或扩展：

- UI 不得复制碰撞、承重、占用算法。
- 模组不得复制碰撞、承重、占用算法。
- 网络层不得复制碰撞、承重、占用算法。
- 不得修改当前三维占地规则本身。
- 不得借同步 Runtime 边界之名重写三维占地迁移设计。
