## 建议写入内容

待 Codex / 用户审核后回写。

### 一、第一批回写总原则

第一批正式回写应遵守：

- 只回写 MVP 范围冻结与基础城市闭环。
- 不新增玩法系统。
- 不写 Runtime 代码。
- 不修改存档结构、StateHash、联机协议或测试代码。
- 不把任务、商店、地下、工具、熔炉、铁矿石、铁锭、燃料链写成 MVP 必做。
- 必须明确 MVP 是小型体素城市样机，不是缩小版完整游戏。
- 必须明确房屋、农田、水井、树场是 MVP 四个基础建筑。
- 必须明确 NPC 只做简化劳动力、施工、入住、工位反馈，不做完整人生模拟。
- 必须明确 UI 只做解释与轻提示，不做强制任务、商店促销、红点运营。

### 二、建议任务 RW1：前30秒与首次城市响应

建议写入 `00.27 前30秒与首次城市响应规则_v1.md`：

- MVP 首轮体验目标不是展示完整系统，而是让玩家理解城市处于等待启动状态。
- 玩家可以放置第一座基础建筑。
- 第一次合法建造会触发时间推进、施工反馈、资源变化和 NPC 响应。
- 前30秒允许出现初始地皮、资源栏、时间暂停状态、建造入口、四个基础建筑卡、少量 NPC 存在感和一个非强制轻提示。
- 前30秒不得自动打开任务、商店、地下、工具、科技、完整 NPC 管理、联机或模组面板。
- 第一次合法建造后应触发资源扣除或锁定、施工状态、NPC 施工响应、建筑详情状态和下一步轻提示。

### 三、建议任务 RW2：基础城市闭环

建议写入 `4.2 生产链路总览.md`：

MVP 基础城市闭环为：

木材驱动建造 → 房屋提供居住容量 → 水井提供水 → 农田消耗水并产出食物 → 城市按人口聚合消耗食物与水 → 空闲 NPC 自动补位到生产 / 施工岗位 → 树场提供可再生木材继续扩张。

该闭环是 MVP 的唯一核心生产链。

MVP 生产链到“树场提供可再生木材”即停止，不继续展开熔炉房、铁矿石、铁锭、燃料链、工具制造链、地下矿脉、商店补货、任务奖励资源池。

### 四、建议任务 RW3：MVP 资源范围

建议写入 `4.1 全资源清单.md`：

MVP 必须进入主循环的资源 / 状态项：

- 木材：基础建造与扩张资源。
- 食物：维持人口、体现农田价值。
- 水：维持人口、支撑农田生产。
- 人口：城市规模与住房容量的核心状态。
- 空闲工人：施工与生产岗位调度的核心状态。

MVP 不进入主循环的资源：铁矿石、铁锭、燃料、木炭、煤炭、铜矿石、水晶碎片、晶能、工具、高级建筑材料、商店货币扩展项。

### 五、建议任务 RW4：MVP 建筑通用规则

建议写入 `2.1 建筑通用规则.md`：

MVP 阶段只要求以下基础建筑进入主循环：房屋、农田、水井、树场。

MVP 建筑通用流程为：选择建筑 → 放置预览 → 合法性检查 → 确认建造 → 扣除或锁定资源 → 进入施工状态 → NPC 施工响应 → 完成建筑 → 建筑进入运行 / 可用状态 → 建筑详情显示状态与等待原因。

MVP 建筑放置至少检查：是否在可建地皮内、是否占地冲突、是否满足基础地形 / 地基要求、是否至少有一个入口可达或可解释、是否资源足够、是否属于当前 MVP 允许建造建筑。

小草、碎石、贴图颗粒、法线起伏、粒子、阴影等视觉细节不得单独阻止建筑放置。

### 六、建议任务 RW5：四个基础建筑详情

房屋：MVP 中承担居住容量、自动入住反馈、人口 / 居住容量状态、第一轮城市活起来的核心反馈；不实现家庭关系、生育、舒适度、情绪、社交、个体记忆或复杂室内模拟。

农田：MVP 中承担消耗水、周期产出食物、占用基础工位、显示缺水 / 缺工人 / 产物待转移等等待原因；不实现多作物、季节、肥料、病虫害、土壤肥力、复杂光照或地下水系统。

水井：MVP 中承担基础水来源、支撑人口维持、支撑农田生产、显示运行 / 等待工人 / 产水反馈；不实现地下水位、水质、污染、水桶物流、井深升级或地下探索联动。

树场：MVP 中承担可再生木材来源、城市继续扩张能力、基础工位和产木反馈；不实现逐棵树模拟、林业生态、应急炭化、燃料链、工具效率链或复杂采伐路径。

### 七、建议任务 RW6：NPC 最小劳动力

建议写入 `3.3 工作分配逻辑.md`：

MVP 中 NPC 的作用是让城市活起来，但不做完整人生模拟。

MVP 必须真实保留：人口数、空闲 / 占用工人、施工参与、基础生产岗位占用、房屋入住状态、城市级食物 / 水消耗、建筑运行 / 等待原因中的工人状态。

MVP 不实现：职业成长、情绪、恐惧、社交、好感度、个体记忆、完整路径驱动生产结算、个体吃饭喝水行为、个体生命周期细节、家庭关系。

屏幕上的移动和动画可以是表现层，但岗位占用必须是权威状态；没有空闲工人时，建筑详情 UI 应显示“等待工人”。

### 八、建议任务 RW7：MVP UI 最小解释力

建议写入 `5.1`、`5.2`、`5.3`、`5.4`：

全局 UI 至少包含木材、食物、水、人口、空闲工人、时间 / 暂停状态、建造入口和轻量下一步提示。

建造 UI 只展示四张基础建筑卡：房屋、农田、水井、树场。每张卡至少显示建筑名称、简短用途、成本、是否推荐、是否当前可建。

建筑详情 UI 至少显示建筑名称、当前状态、施工 / 运行 / 暂停、工位状态、输入资源、输出资源、等待原因、可用 / 不可用原因。不得只显示“停产”或“错误”。

NPC UI 只显示总人口、空闲工人、占用工人、施工中人数、生产岗位占用、房屋入住状态。不展示完整职业、情绪、恐惧、好感、社交、记忆、家庭关系。

## 理由

待 Codex / 用户审核后回写。

提出本建议的理由如下：

1. 当前已经完成综合裁决与暂存建议分级，下一步应进入第一批正式回写方案，而不是继续新增玩法主题。
2. 第一批回写如果不先拆成具体文件和具体内容，Codex 很容易一次性吸收所有暂存区建议，导致 MVP 膨胀。
3. A 级建议中也包含一些容易扩大范围的内容，必须只吸收 MVP 最小部分。
4. 第一批应优先解决“文档上到底什么是 MVP”，而不是直接进入 Runtime 架构或代码实现。
5. 房屋、农田、水井、树场四个基础建筑必须先写清 MVP 职责，防止各自扩成完整独立系统。
6. NPC 必须保留最小真实劳动力状态，但不能进入职业、情绪、记忆、社交等复杂系统。
7. UI 必须保证玩家能理解状态和下一步，但不能变成任务、商店、运营红点系统。
8. 把 Runtime 架构放到第二批更安全，因为第一批先冻结范围，第二批再冻结代码边界。
9. 本方案能作为后续 Codex 回写前的审查依据。
10. 本轮仍保持暂存区安全流程，不直接修改正式目录。
