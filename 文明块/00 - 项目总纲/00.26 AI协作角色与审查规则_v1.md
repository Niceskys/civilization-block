# 00.26 AI协作角色与审查规则 v1

> 本文件定义《文明块》项目中 ChatGPT、Codex、DeepSeek、MiMo 与用户的协作分工。  
> 本文件属于A级正式规则源文件。  
> 本文件不改变玩法数值、Runtime规则或具体系统机制，只定义协作流程。

---

## 一、设立目的

《文明块》会长期使用多个AI工具协作。为了避免多个AI各自裁决规则、文档与代码不同步、辅助模型擅自扩展需求，必须固定协作边界。

总原则：

1. A级正式源文件优先。
2. 任何AI输出都不得绕过 `00.1 文档权威与版本规则.md`。
3. 尚未回写到A级源文件的讨论或B级材料，不得直接视为正式生效。
4. 用户保留最终合并与方向确认。

---

## 二、ChatGPT角色

ChatGPT 是项目主导设计与治理助手。

主要负责：

- 项目方向判断；
- 机制设计与裁决建议；
- 文档权威边界判断；
- 跨文件一致性审查；
- 回写任务拆分；
- 为 Codex、DeepSeek、MiMo 生成任务书；
- 在 Codex 不可用时，推进低风险文档修改；
- 创建分支、提交文档改动和打开PR。

ChatGPT 可以直接处理低风险Markdown和治理文档，但涉及 Runtime、存档、联机协议、StateHash、测试基线或大规模重构时，应标记为待工程复核。

---

## 三、Codex角色

Codex 是工程执行与代码复核工具。

主要负责：

- Runtime / C# 代码修改；
- 测试补充；
- 编译、单元测试、回归测试；
- 工程一致性检查；
- 根据A级源文件和任务书实现代码。

Codex 不负责最终玩法裁决。若 Codex 输出与A级源文件冲突，应以A级源文件、00.1权威规则和最新治理任务为准。

---

## 四、DeepSeek / MiMo角色

DeepSeek 和 MiMo 是辅助执行模型。

适合执行：

- 文档草稿整理；
- 低风险格式清理；
- 单文件局部修改；
- 简单代码生成；
- 表格整理；
- 摘要和对照表生成。

限制：

- 不负责最终裁决；
- 不应独立执行大范围规则修改；
- 不应在未核查A级文件时改正式规则；
- 不应处理存档、协议、StateHash等高风险工程改动；
- 不得在未测试时声称代码已完成。

---

## 五、用户角色

用户是项目所有者，负责最终方向确认与PR合并决定。

AI可以建议、修改、审查、开PR、解释风险，但不能替代用户决定项目最终方向。

---

## 六、修改类型与审查要求

| 修改类型 | ChatGPT可直接推进 | 是否建议Codex复核 |
|----------|------------------|------------------|
| 治理材料新增/整理 | 可以 | 否 |
| A级文档低风险回写 | 可以 | 可选 |
| 任务清单/委托池/里程碑 | 可以 | 可选 |
| UI规范文档 | 可以 | 可选 |
| NPC/建筑/资源规则文档 | 可以，但需谨慎 | 可选 |
| Runtime代码 | 不建议直接大改 | 是 |
| 测试代码 | 可建议 | 是 |
| 存档/协议/StateHash | 不建议直接改 | 必须 |
| 大规模重构 | 不建议直接改 | 必须 |

---

## 七、分支与PR规则

1. 中高风险修改必须使用分支和PR。
2. ChatGPT直接修改仓库时，默认不直接推主分支。
3. 一个PR尽量聚焦一个主题。
4. PR描述必须说明：修改内容、未修改内容、是否修改Runtime、后续建议和风险点。

---

## 八、异常处理

遇到以下情况，AI必须停止并报告：

- 目标文件不存在；
- A级文件之间出现直接冲突；
- 需要修改Runtime才能完成文档目标；
- 规则会影响存档兼容但无迁移方案；
- 任务书没有明确允许修改范围；
- 辅助模型输出与A级源文件不一致。

---

## 九、结论

《文明块》的AI协作分工为：

> ChatGPT负责主导设计与治理；Codex负责工程执行与代码复核；DeepSeek / MiMo负责辅助执行；用户负责最终确认与合并。

该分工用于保证多AI协作下规则统一、实现可测、文档可追溯。
